# Kotlin 语料模块-开发计划

- **日期**：2026-09-07
- **背景**：插件 Kotlin wrapper 支持（IService 的 ktQuery()/ktUpdate() 扩展链，KtWrapperDetector 文本正则 MVP）在 MP-MPJ 覆盖矩阵中标 ✅，但 demo 三模块均为纯 Java，Kotlin 路径零语料。其他 ORM（jOOQ/Querydsl/Spring Data JDBC 等）为 M44+ 未立项框架，本轮不建。
- **目标**：新建 `mybatis-plus-kotlin-demo` 独立 Maven 模块，为插件 Kotlin 检测路径提供真实语料。

## 一、API 与检测器核验（javap / 源码为准）

1. MP 3.5.3.1 扩展包原生提供 `IService.ktQuery()/ktUpdate()`（javap 证实），KtQueryChainWrapper/KtUpdateChainWrapper/KtQueryWrapper/KtUpdateWrapper 类齐全。
2. 插件 `KtWrapperDetector` 为**逐行正则 MVP**：
   - 链起点 `.ktQuery(`/`.ktUpdate(` 或直接构造 `LambdaQueryWrapper<`/`QueryWrapper(` 等（含 MPJ 两类名）；
   - 链上调用必须在**同一行**才被收集（`.method(` 正则 + 白名单方法名）；
   - 注释行仅跳过 `//` 开头——注释中不得出现「构造名+`(`/`<`」字样，否则误触发。
3. 版本墙：MP 3.5.3.1 无 `LambdaDeleteWrapper`（3.5.4+），条件删除用 remove(updateWrapper) 惯用法替代；Kotlin 关键字 `in` 需反引号调用，MVP 正则不识别（含 PSI 深化后再验）。
4. Kotlin 反引号与尾随 lambda（`.and { ... }`）无括号不匹配正则——语料一律用 `.and({ w -> ... })` 带括号形态。

## 二、实施内容

1. 新模块 `mybatis-plus-kotlin-demo`：Spring Boot 2.6.3 + MP 3.5.3.1 + Kotlin 1.9.25（本地缓存），kotlin-maven-plugin，jvmTarget 1.8，全 Kotlin 源码。
2. 实体：`KUser`（@TableName/@TableId/@TableLogic/@Version）、`KOrder`；Mapper/IService/ServiceImpl 常规三层。
3. 语料集中类 `KotlinWrapperScenarios`（全部单行链）：
   - ktQuery：eq/ne/gt/le、like 族、between、isNull/isNotNull、notIn、select 多列、groupBy/having、apply、last、or/and 带括号嵌套、布尔开关重载；
   - ktUpdate：set（含开关重载）/setSql/notIn/update/remove；
   - 直接构造：Lambda 系查询/更新、字符串版 Query/Update 两系、Kt 系包装（子串匹配边界用例——类名含 QueryWrapper 子串，插件按 QUERY 形态识别）；
4. Controller 挂载全部场景；根 pom 注册模块；全量编译回归。
5. README 场景覆盖清单补 Kotlin 一节（含书写约束与 MVP 边界说明）。

## 三、验收

1. `mvnd compile` 全模块零错误。
2. IDEA 打开后 `.kt` 语料文件中 ktQuery/ktUpdate/直接构造链行出现插件 gutter 图标（人工抽验）。
