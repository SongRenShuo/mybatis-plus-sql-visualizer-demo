# 插件测试语料全方位补齐-开发计划

- **日期**：2026-09-18
- **目标**：对照插件（Sql Visualizer，当前 2026.9.18-beta.4，识别域 M1~M56）的最新能力矩阵，全方位补齐 demo 仓库缺失的测试语料，重点补上插件已支持而 demo 零覆盖的「其它 ORM 四家」（xbatis / Easy-Query / MyBatis Dynamic SQL / Querydsl），以及 Wrapper 定位器高级形态、MPJ 工厂与终结点、JPA 存储过程等零散缺口。
- **范围**：仅 demo 仓库；不改插件代码。编译通过为硬门禁，每个里程碑独立 git 提交。

## 四、风险与约束

- **版本墙**：见第一节清单，全部 javap 实证后不写，防止「调用不存在的 API」。
- **编译门禁**：每个里程碑 `mvnd compile` 零错误才提交；新 API 先 javap 后落笔。
- **APT 双处理器**（M4）：JDK 8 javac classpath 探测双 processor 理论可共存；冲突即拆分，不让门禁带病通过。
- **共存验证**（M4）：三个 ORM 共用一数据源在真实项目常见；若启动互踩，以 `-Dspring.autoconfigure.exclude` 逐家隔离排查，不影响静态语料有效性（插件识别按方法名超集，与运行无关）。
- **不改既有行为**：新增独立 Service/Controller/实体为主；既有文件仅做增方法级扩展。
- **编码**：Java 8 语法；新文件一律 UTF-8（Bash 命令行不写中文）。

## 五、验收标准

1. 每里程碑 `mvnd compile` 零错误、独立 git 提交，提交信息注明场景范围。
2. M4 后新模块可启动（orm_demo 库初始化成功），端点可访问（人工抽验项）。
3. 新场景在 IDEA 打开后：正例出 gutter、负例（M5）零 gutter（人工抽验项，写入 README 供测试对照）。
4. README 覆盖清单与实际代码一致。
